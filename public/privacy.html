Fact Check Privacy Policy

Effective and last updated: 24 July 2026

This Privacy Policy explains how the Fact Check Chrome extension ("Fact Check") handles information. Fact Check is operated by Natanael Rehuel Santoso ("the developer").

1. Purpose and scope

Fact Check has one purpose: to help a user evaluate factual claims from a webpage, a public article URL, or text the user chooses to submit. This policy applies to the Chrome extension and the hosted Fact Check backend. It does not replace the privacy policies or terms of the third-party services listed below.

Fact Check does not continuously monitor browsing history. Page access is used only when the user opens or refreshes the extension for a page, or asks the extension to locate a checked claim on that page.

2. Information processed

Content selected for checking

  • Readable page text and related article metadata, such as the page URL and title, when the user checks the current page.
  • A public article URL when the user chooses URL mode.
  • Text entered or pasted by the user when the user chooses text mode.
  • Claims, search queries, evidence excerpts, source links, verdicts, explanations, errors, and other results produced during a check.

Submitted content may contain personal or sensitive information if the user includes it. Users should not submit confidential information or information they are not authorized to process.

Provider credentials

Fact Check uses a bring-your-own-key model. It processes the Gemini API key and Tavily API key entered by the user so that Google and Tavily can authorize the requests the user starts. The keys are not developer-owned credentials.

Technical and usage information

  • A randomly generated installation identifier used to apply abuse and rate limits. It is not an account identifier.
  • Network information processed by the backend and hosting provider, including an IP address, request time, request path, and ordinary connection metadata.
  • A random job capability token used to restrict access to a check while it remains available.
  • Provider-usage information, such as Gemini token counts, Tavily search attempts, and estimated Tavily credits.

Fact Check does not use cookies, advertising identifiers, analytics SDKs, or cross-site tracking.

3. How information is used

The information described above is used only to:

  • read the page or input selected by the user;
  • extract factual claims;
  • find candidate evidence and compare claims against that evidence;
  • display, retry, export, or temporarily restore the user's check;
  • show provider-usage totals;
  • secure the service, enforce capacity and rate limits, diagnose failures, and prevent abuse; and
  • comply with applicable legal obligations.

The developer does not use submitted content, browsing activity, provider keys, or results for advertising, credit decisions, data brokerage, or training a developer-owned AI model.

4. Service providers and data transfers

Information is sent only to services needed to perform the check:

  • Railway hosts the backend and therefore processes requests, submitted content, provider-key headers, results held in backend memory, and network metadata. See the Railway Privacy Policy.
  • Google Gemini API receives submitted text for claim extraction and receives claims and evidence excerpts for verification. The user's Gemini key authorizes these requests. Google's treatment of API data can differ between unpaid and paid services; users should review the Gemini API Additional Terms and Google Privacy Policy. Google states that content submitted to certain unpaid Gemini services may be used to improve its products and may be reviewed by humans. Do not submit sensitive, confidential, or personal information when using an unpaid service.
  • Tavily receives claim-derived search queries and the user's Tavily key, and returns candidate web evidence. See the Tavily Privacy Policy.
  • Jina AI Reader receives the public URL entered in URL mode so it can retrieve readable article content. It is not used for pasted-text checks or checks that use page text captured directly by the extension. See Jina AI Legal Information.

These providers may process information in countries other than the user's country and apply their own retention, security, and legal terms. Fact Check does not control their independent processing.

5. Storage and retention

In Chrome

  • Provider keys, drafts, captured page data, active-job recovery information, and results are stored in chrome.storage.session for the current Chrome profile. Provider-key storage is restricted to trusted extension contexts. It is cleared when the browser session ends or the extension is reloaded, updated, or disabled. Closing only the side panel does not clear it.
  • The random installation identifier is stored in chrome.storage.local and remains until the extension is removed or its storage is cleared.
  • Exports are created only when the user requests them and are saved to the download location selected by Chrome.

Chrome extension storage is not a substitute for an encrypted password manager. Users can clear their provider keys from the extension at any time and should revoke a key with Google or Tavily if they believe it has been exposed.

In the backend

  • Submitted content is held in process memory while a check runs.
  • Job status, claims, evidence, results, errors, and usage totals are held in process memory. They become eligible for removal one hour after the job reaches a final state and are removed during subsequent backend cleanup. A backend restart removes them sooner.
  • IP-address and installation-identifier entries are used during the configured short rolling rate-limit window. Stale entries are removed during subsequent backend cleanup, and a backend restart removes them sooner.
  • Provider keys are used only by the job or retry that received them. They are not written to a database, job snapshot, event stream, result export, or application log, and provider-client references are cleared when the operation finishes.

The hosting provider may retain infrastructure and access logs under its own policy. Fact Check deliberately avoids logging request bodies and provider keys, but no internet service can guarantee that operational metadata will never be retained by its infrastructure provider.

6. Sharing, sale, and human access

The developer does not sell, rent, trade, or license user information. Information is shared only with the service providers above when necessary to provide the requested fact check, to protect the service from abuse, or when required by law.

The developer does not routinely read submitted content. Human access would be limited to information a user deliberately includes in a support report, information needed to investigate a security or abuse incident, or information required by law. Third-party providers may have different human-review practices as described in their own policies and terms.

7. Chrome permissions

  • activeTab allows access to the page where the user invokes Fact Check.
  • scripting extracts readable page text and locates a checked claim on the open page.
  • sidePanel displays the Fact Check interface.
  • storage stores temporary session state, provider keys, and the installation identifier described above.
  • Backend host access allows encrypted requests to the hosted Fact Check API.
  • Optional website access is requested when the user asks the extension to refresh page content after navigating to another page.

8. Security

Hosted requests use HTTPS. Production browser-origin access is limited by CORS to the configured published extension origin, API responses are marked not to be cached, provider credentials are isolated per job, and job results require a random capability token. These controls reduce risk but cannot guarantee absolute security.

9. User choices and deletion

  • Do not start a check if you do not want the selected content sent to the backend and the applicable providers.
  • Clear provider keys from the key dialog, or fully exit Chrome to end the session.
  • Remove the extension or clear its extension storage to delete the persistent installation identifier.
  • Cancel an active check from the side panel. A provider request already in progress may continue until its timeout.
  • Manage or revoke provider keys directly through Google AI Studio and Tavily.

Fact Check has no user accounts and does not maintain a user database. Backend jobs expire automatically as described above. For privacy questions, emailnatanaelrehuels@gmail.com. Do not include API keys, passwords, confidential source text, or other sensitive information in your email.

10. Children

Fact Check is not directed to children under 18. Google states that users of the Gemini API must be at least 18. Do not use Fact Check if you do not meet the age requirements of the provider services connected through your keys.

11. Changes to this policy

This policy may be updated when Fact Check's data practices, providers, or legal obligations change. The effective date at the top will be updated. Material changes to data practices will also be disclosed through the extension or its Chrome Web Store listing when required.

12. Chrome Web Store Limited Use disclosure

Fact Check's use and transfer of information received from Google APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements.
